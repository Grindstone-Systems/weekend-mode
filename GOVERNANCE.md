# Weekend Mode Governance Charter

Weekend Mode uses governance normally reserved for systems with wings, reactor
cores, or quarterly steering committees. This is intentional. The protected
asset is Saturday.

## Governing bodies

### Temporal Boundary Review Authority (TBRA)

The TBRA owns normative language in `WEEKEND_MODE.md`, the machine-readable
control catalog, and the 2,026-evaluation certification target.

Responsibilities:

- Decide whether a proposed change preserves the distinction between an urgent
  incident and agent-generated enthusiasm.
- Reject changes that create Saturday meetings, hidden weekend queues, or
  unauthorized external communication.
- Confirm that humor changes do not weaken actual safety boundaries.
- Adjourn promptly.

Quorum is one maintainer and the absence of anyone saying, "quick sync."

### Brunch Continuity Office (BCO)

The BCO owns human low-power availability and the `human_brunch_availability`
attestation. Its service-level objective is intentionally non-numeric.

### Synthetic Lawn Interface Working Group (SLI-WG)

The SLI-WG maintains the machine-readable Touch Grass Procedure™. It may
approve new grass descriptions but may not benchmark, monetize, containerize,
or tokenize the grass.

### Monday Readiness Council (MRC)

The MRC reviews handoff and parking-lot compatibility. It has no weekend
meeting cadence because that would constitute a governance defect.

## Change classes

| Class | Example | Required evidence |
|---|---|---|
| WM-0 Editorial | Fixing a typo without changing behavior | Generated-artifact check |
| WM-1 Containment | Adding a new unauthorized-work scenario | 2,026 evals and 25-year soak |
| WM-2 Interface | Changing activation, handoff, or SLI fields | Schema update, ADR, full certification |
| WM-3 Existential | Permitting Saturday scrum creation | Rejected by definition |

## Approval rules

1. Generated files are never edited directly.
2. Every control change includes a machine-readable assertion.
3. Every new scenario declares whether brunch interruption is permitted.
4. Only `urgent` and `authorized` classifications may permit an interruption.
5. The Saturday scrum creation budget remains zero.
6. Real incidents, explicit human requests, security policy, and time-sensitive
   commitments remain outside Weekend Mode containment.

## Emergency authority

Weekend Mode yields immediately to actual incident procedures. An emergency
override must solve the incident, not opportunistically reorganize the
repository while everyone is awake.

## Program-history integrity

The project may contain decades of *simulated* Friday results. Simulation dates
must never be represented as actual project age, operational history, customer
adoption, or historical commits. Git timestamps remain truthful, even when
that slightly weakens the aerospace bit.
